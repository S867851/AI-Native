# FlowGram 独立服务部署说明

> 历史阶段记录：2026-10-25 已按用户新决定接入 JeecgBoot。当前登录、权限、共享流程与运行记录以 [整合部署与验收](JeecgBoot-FlowGram-整合部署与验收-2026-10-25.md) 为准；下文独立 Basic 登录和单份共享草稿描述仅对应接入前版本。

日期：2026-10-24；验收补充：2026-10-25

## 1. 本次范围

用户明确要求先把 FlowGram 独立部署到测试服务器，作为与当前 JeecgBoot 分开的第二个服务，后续再考虑平台接入。

实现基于官方 FlowGram Web 自由布局示例及 Node.js Runtime，不部署 Desktop 桌面应用，不改用 JeecgBoot 的账号或业务数据库。

## 2. 两个服务

| 服务 | 入口 | 后端 | 数据 |
|---|---|---|---|
| JeecgBoot | http://YOUR_SERVER/agent/ | `jeecg-agent.service`，127.0.0.1:8081 | 既有独立数据库与上传目录 |
| FlowGram | http://YOUR_SERVER/flowgram/ | `flowgram.service`，127.0.0.1:4000 | `/opt/flowgram/data` |

两个入口共用服务器的 Caddy 反向代理与 80 端口，运行进程、源码目录和数据分别管理。此次不新增 JeecgBoot 菜单，不转换原有流程。

FlowGram 使用独立的 HTTP Basic 访问凭据，浏览器首次访问会提示输入账号密码；凭据仅通过当前聊天交付，不写入本文。模型服务密钥未配置。

## 4. 本次必要适配

1. 前端静态资源使用 `/flowgram/` 前缀。
2. 前端试运行连接真实服务端 Runtime，不使用浏览器执行模式。
3. 初始流程为不依赖外部模型的“开始 → 结束”，输入文本原样输出，用于验证真实执行。
4. 官方示例原 Save 逻辑仅打印到控制台。本次将保存按钮接到服务器草稿接口，并在打开页面时加载草稿。
5. 草稿采用服务器 JSON 文件保存，使用临时文件后原子重命名写入；缺失草稿时加载初始流程，读取失败时显示错误，避免静默覆盖。
6. 草稿保存保留节点、连线与全局变量定义。
7. Runtime 仅监听本机，由独立鉴权的反向代理入口提供访问。

## 5. 当前能力与限制

| 项目 | 范围 |
|---|---|
| 编排 | 官方示例提供的节点、画布、表单、变量与连线能力 |
| 试运行 | 服务端 Start→End 真实执行通过；当前浏览器 LLM 草稿未满足运行条件 |
| 保存 | 单份共享草稿，点击 Save 后写入服务器；没有自动保存和多项目管理 |
| 草稿重开 | 读取服务器草稿；支持服务重启后保留 |
| 运行历史 | 使用参考 Runtime 的内存任务状态，重启后不保留完整执行历史 |
| 并发编辑 | 未提供版本冲突解决，后保存的草稿会覆盖先前版本 |
| 外部模型 | 尚未接入真实凭据，不能把初始流程成功当作模型调用成功 |
| 音频转写 | 尚未开发本项目专用节点及服务适配 |
| JeecgBoot 对接 | 本次不实施 |
| 使用定位 | 独立测试工作台，尚非完整生产 Agent 平台 |

## 6. 服务器目录与运行管理

| 内容 | 位置 |
|---|---|
| 安装根目录 | `/opt/flowgram` |
| 页面 | `/opt/flowgram/web` |
| 运行时与生产依赖 | `/opt/flowgram/runtime` |
| 源码快照 | `/opt/flowgram/source` |
| 持久化草稿 | `/opt/flowgram/data/workflow.json` |
| 上传产物和部署脚本 | `/home/ubuntu/flowgram-test` |
| systemd 单元 | `/etc/systemd/system/flowgram.service` |
| 服务日志 | `journalctl -u flowgram` |

运行时初始限制：Node 堆上限 128MB、systemd 内存上限 256MB。限制用于控制测试环境资源，不能作为已通过容量验收的结论。

```bash
sudo systemctl status flowgram
sudo journalctl -u flowgram -n 100 --no-pager
sudo systemctl restart flowgram
```

停止 FlowGram 可使用 `sudo systemctl stop flowgram`，不需要停止 JeecgBoot。

## 8. 用户验收步骤

1. 打开 FlowGram 入口，用独立凭据进入。
2. 运行初始流程，输入任意测试文字，检查输出一致，并查看节点执行状态。
3. 调整节点标题，点击 Save，确认成功提示。
4. 刷新页面，检查修改仍在。
5. 逐步添加 HTTP、模型或其他节点验证；外部模型与转写需另配服务。
